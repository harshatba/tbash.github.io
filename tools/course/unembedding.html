From vector to a next-word guess

We finally have a final vector for the predicting position. To turn it into a word, score it against every token in the vocabulary with the very same dot product from lesson 2 — one score per word — then softmax. That's the whole trick behind "next token: cat, 61%."

⏱ ~5 min 🎚 rank the vocab, computed math: one dot per word

After attention and the feed-forward step, the last position of "The cat sat because it was ___" holds one 4-number vector. It doesn't spell a word — it's a point in meaning-space. So we ask a simple question: which vocabulary token does this vector point at most?

Score it against every token by dotting it with that token's embedding row. Reuse the embedding table E backwards: one dot product per word gives one raw score — a vocab-logit — and softmax turns the whole list into next-token probabilities. (Real models often reuse the very same E, transposed — "tied weights.") This is the exact a·b from lesson 2, now scoring the output vector against the whole dictionary instead of scoring two words against each other.

Two different logit lists — name the difference now. Lessons 6–7 made attention-logits: one score per token in the context (~7 here). This page makes vocab-logits: one score per word in the whole vocabulary (7 here, ~50,000 in a real model). Same softmax formula, two completely different lists — never call one "the logits" without saying which.

Predicted next token = tired at 30.3% (Σ = 100.0%). So "cat 61%" in any explainer is exactly this: the final vector dotted against every embedding row, softmaxed — nothing more exotic. The runners-up cat and it are the sentence's subject, which is a sensible next-guess for "…it was ___".

Attention-logits vs vocab-logits. Lesson 6's seven scores were one-per-token in the context — q·k, softmaxed into attention weights (how much to listen to each token). These seven are one-per-word in the vocabulary — the final vector dotted against every row of E, softmaxed into next-token probabilities. Same softmax formula, different lists. Here both lists happen to be length 7; in a real model the first is a few thousand and the second is ~50,000.

MythPredicting the next word is a special lookup, or a separate classifier head with its own giant table.
RealityIt's the same dot product as similarity, run against every embedding row. The model scores its final vector against the whole vocabulary and softmaxes — often reusing the very same embedding table, transposed.
Takeaway

To turn a vector into a word: dot it against every row of the embedding table → one vocab-logit per word → softmax → next-token probabilities. That's where "next token: cat, 61%" comes from.

Where does "next token: cat, 61%" come from?
Why: the unembedding scores the output vector against every vocabulary token with one dot product each — those are the vocab-logits — and softmax turns them into next-token probabilities. Attention weights (attention-logits) are a different list entirely.
