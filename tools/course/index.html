Part 1 · How LLMs Work

From a token ID to the next word — meaning, attention, and the full forward pass, every number computed live.

  1. 01 Where does the vector come from? Read a token's vector straight out of the learned lookup table, by row. →
  2. 02 Nearby vectors mean similar things Rank every token by dot-product similarity to an anchor you pick. →
  3. 03 Meaning has directions you can do arithmetic with Compute A − B + C on real vectors and watch the nearest word fall out. →
  4. 04 One neuron: multiply, add, squish Slide the inputs and watch each multiply, the running sum, and the tanh squish. →
  5. 05 Query, Key, Value: three vectors from one token Turn one embedding into its Q, K and V through three different weight matrices. →
  6. 06 How attention actually computesflagship Watch Q·K dot products → softmax weights that sum to 1 → a blended Value vector, live. →
  7. 07 Many heads, many kinds of attention Toggle heads and watch the same token get routed three different ways. →

  8. Act 2 · from attention to a word — the forward pass

  9. 08 Where does the blended vector go? Add attention's blend back onto the token's own vector — refine, don't replace. →
  10. 09 The feed-forward step: each token thinks alone Run the lesson-4 neuron across a real post-attention token vector. →
  11. 10 From vector to a next-word guess Dot the final vector against every embedding row to rank the next word. →
  12. 11 Three dials on the next-word distribution Reshape the probabilities with temperature, top-k, and top-p. →
  13. 12 One block, stacked N times Stack attention + FFN + residual and watch a token's vector drift over layers. →
  14. 13 Meaning + position, literally added Add position to meaning, element-wise: "dog bites man" vs "man bites dog". →
  15. 14 Why models hallucinate See a confident, false token outrank the true one — no truth-check anywhere. →
  16. 15 Why it can't count the r's in "strawberry" Watch "strawberry" become opaque IDs the letter-count can't survive. →

Part 2 · How LLMs Run Fast

Same model, now served in milliseconds. Eight pages, one lever each — and every FLOP, byte, and token-per-second is computed live from one 7B-class model preset.

  1. 01 Reading the prompt is fast; writing is slow Compute prefill vs decode time and watch decode dominate (~156×). →
  2. 02 The KV cache: don't recompute the past Count the triangular blow-up of recomputing every past token's K/V. →
  3. 03 The cache grows and eats VRAM Size the KV cache live: layers × heads × dim × seq × 2 × bytes. →
  4. 04 Store each weight in fewer bits Snap weights onto int8/int4 levels; watch memory drop 4×. →
  5. 05 Paged attention: stop reserving unused memory Compute padding waste for reserve-max vs paged (~75% → ~1%). →
  6. 06 Read the weights once, serve many Compute GPU utilization and throughput for static vs continuous. →
  7. 07 Guess ahead, verify in one pass Compute expected tokens/step and speedup from an acceptance rate. →
  8. 08 The roofline: moving weights, not maththe why Compute arithmetic intensity and land below the ridge point. →
